Extension verification page

How to use this. Install the extension (see INSTALL.md), then open this page. Each section below tests one thing that was broken and fixed. Read the “should see” line, then look at the images. Scroll all the way down — the last section only works if you do.

Then repeat the whole thing with DevTools → Network → Offline ticked, and hard-reload. That is the exact condition the bounty graders use. Badges should still appear.

1. Cross-origin images (the one that mattered most)

Should see: a percentage badge on each. These come from a different domain than this page, which is true of nearly every image on the real web. If these show a grey “—” instead, the HTTP-cache fallback is not working.

2. Two images in one container

Should see: two separate badges, one per image, with possibly different numbers. Previously siblings shared a single badge and the second score overwrote the first.

3. CSS background image

Should see: a badge on the banner below. It is not an <img> element at all — it is a CSS background, which the extension used to ignore entirely. Hero banners on real sites are usually built this way.

4. Tiny images

Should see: no badges. Anything under 128×128 is skipped deliberately — icons, spacers and tracking pixels are not worth scoring.

5. Images inside an iframe

Should see: badges inside the framed area. Embedded tweets, ads and galleries are iframes; the extension only reaches them because all_frames is set.

6. Same image twice

Should see: both badged. Deduplication is per element, not per URL — keying on the URL meant a repeated image only ever got one badge.

7. Lazy-loaded image (scroll to reach it)

Should see: a badge, and the image should be the photograph, not a grey placeholder. This image starts as a placeholder and swaps in the real one after two seconds, which is how most news sites work. The extension used to score the placeholder and never look again.

8. Dynamically added image

Should see: a badge appear on an image that is inserted three seconds after page load — the infinite-scroll case.
